# Chapter 6: 数据工程

## Core Idea
本章讲数据如何从采集到治理形成资产：数据规划、采集、治理、集成共享与数据管理，是数字中国"数据要素"在工程层面的落地，也是新一代项目的数据底座章。

## Frameworks Introduced
- **数据工程全流程**：数据规划 → 数据采集 → 数据治理 → 数据集成与共享 → 数据管理。
- **数据规划**：基于业务架构识别数据需求，建立数据资产目录与数据标准。
- **数据采集**：ETL（抽取/转换/加载）、流式采集、物联网边缘采集。
- **数据治理**：数据质量、元数据、主数据（MDM）、数据血缘、数据确权与安全合规。
- **数据集成与共享**：数据湖/数据仓库、API 共享、数据中台。
- **数据管理成熟度**：DCMM（数据管理能力成熟度）分级。

## Key Concepts
- **主数据（MDM）**：跨系统共享的核心业务实体（客户/产品/组织）。
- **元数据**：描述数据的数据。
- **数据要素**：数据作为生产要素参与分配与流通。

## Mental Models
- 数据类项目出问题，先查"治理"是否到位（标准/质量/主数据），再查采集与集成管道。
- 谈数据价值，套"确权—流通—收益分配"的要素化逻辑。

## Anti-patterns
- 把数据集成等同于"导库"，忽视数据标准与主数据一致性。
- 重采集轻治理（有数据无质量、无血缘）。

## Key Takeaways
1. 数据工程五步：规划→采集→治理→集成共享→管理。
2. 治理核心：标准/质量/主数据/元数据/血缘/合规。
3. 集成用数据湖/仓 + API 共享 + 数据中台。
4. 数据管理能力看 DCMM 成熟度。
