# Chapter 14: 收尾过程组

## Core Idea
收尾过程组正式结束项目、阶段或合同，完成验收、移交与总结。中项第3版收尾过程组含 **1 个过程**：结束项目或阶段，并强调收尾的重点工作（验收/移交/总结）。

## Frameworks Introduced
- **收尾过程组（1 过程）**：结束项目或阶段（输出最终产品/服务移交、项目文件归档、经验教训、释放资源）。
- **收尾重点工作**：
  - 项目验收：依据合同与需求确认成果合格。
  - 项目移交：可交付成果与文档交付客户/运维方。
  - 项目总结：经验教训登记册、绩效复盘。
- **合同收尾 vs 管理收尾**：采购合同关闭（核实交付、结清款项）与项目行政收尾（归档、释放资源）。

## Key Concepts
- **经验教训登记册**：收尾沉淀，供后续项目复用。
- **提前终止**：项目因目标不可达/资金中断等提前结束，也须走收尾。
- **资源释放**：团队与设备回归组织。

## Mental Models
- 收尾不是"干完就走"：验收→移交→总结→归档→释放资源，缺一不可。
- 合同收尾先于/并行于管理收尾，采购未关闭不算真正收尾。

## Anti-patterns
- 跳过验收直接上线（无验收记录，责任不清）。
- 项目结束不写经验教训，重复踩坑。

## Key Takeaways
1. 收尾 1 过程：结束项目或阶段。
2. 收尾三步：验收 → 移交 → 总结。
3. 区分合同收尾与管理收尾。
4. 经验教训登记册是必产出的知识资产。
