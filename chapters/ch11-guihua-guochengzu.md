# Chapter 11: 规划过程组

## Core Idea
规划过程组明确项目全部范围、定义并优化目标、制定行动方案，是项目成败的决定性阶段。中项第3版规划过程组含 **24 个过程**，输出项目管理计划与各项目文件；计划批准后即成为"基准"。

## Frameworks Introduced
- **规划过程组（24 过程，按知识领域）**：
  - 整合：制订项目管理计划
  - 范围：规划范围管理、收集需求、定义范围、创建 WBS
  - 进度：规划进度管理、定义活动、排列活动顺序、估算活动持续时间、制订进度计划
  - 成本：规划成本管理、估算成本、制定预算
  - 质量：规划质量管理
  - 资源：规划资源管理、估算活动资源
  - 沟通：规划沟通管理
  - 风险：规划风险管理、识别风险、实施定性风险分析、实施定量风险分析、规划风险应对
  - 采购：规划采购管理
  - 干系人：规划干系人参与
- **渐进明细**：规划随信息增加迭代细化，持续进行直至得到可行计划。
- **基准**：经批准的项目管理计划（范围/进度/成本基准）作为绩效测量依据。

## Key Concepts
- **WBS（工作分解结构）**：以可交付成果为导向的层次分解，100% 原则，工作包为最底层。
- **需求跟踪矩阵**：需求从提出到交付的双向追溯。
- **滚动式规划**：近期细、远期粗。

## Mental Models
- 规划顺序：先定各管理计划 → 范围(WBS) → 资源 → 进度 → 成本 → 质量 → 采购/风险/沟通/干系人计划。
- 计划不是一次成型，重大变更会触发重新规划（渐进明细）。

## Anti-patterns
- WBS 漏分解或违反 100% 原则（范围蔓延隐患）。
- 把"估算活动资源"算进进度管理（中项里资源规划含估算活动资源，与高项口径一致但归资源管理域）。

## Key Takeaways
1. 规划过程组共 **24 个过程**（整合1/范围4/进度5/成本3/质量1/资源2/沟通1/风险5/采购1/干系人1）。
2. 计划批准后成"基准"，监控据此比对。
3. WBS 是范围核心，100% 原则。
4. 渐进明细≠范围蔓延。
