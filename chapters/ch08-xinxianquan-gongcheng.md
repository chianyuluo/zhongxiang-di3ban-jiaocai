# Chapter 8: 信息安全工程

## Core Idea
本章从工程化视角落地信息安全：以等保 2.0 为主线，覆盖风险评估、安全规划/设计/实施/运维/测评全流程，是系统集成项目合规交付的硬性要求章。

## Frameworks Introduced
- **信息安全基本属性**：CIA——保密性（Confidentiality）、完整性（Integrity）、可用性（Availability），扩展含可控性、不可否认性。
- **等保 2.0（网络安全等级保护）**：1–5 级（用户自主保护→系统审计保护→安全标记保护→结构化保护→访问验证保护），由低到高；"一个中心、三重防护"= 安全管理中心 + 通信网络/区域边界/计算环境。
- **等保实施流程**：定级 → 备案 → 建设整改 → 等级测评 → 监督检查（三级以上每年测评）。
- **风险评估**：风险 = f(资产, 威胁, 脆弱性)；步骤为资产识别→威胁识别→脆弱性识别→风险分析→风险处置。
- **安全工程生命周期**：安全规划 → 安全设计 → 安全实施 → 安全运维 → 安全测评。
- **关键信息基础设施（关基）**：重点保护对象，等保之外再加护。

## Key Concepts
- **纵深防御**：边界→网络→主机→应用→数据多层设防。
- **密码应用**：商用密码合规（密评）。
- **数据安全法/个人信息保护法**：数据处理活动合规底线。

## Mental Models
- 安全方案先"定级"（等保几级）再"三重防护"落地，最后持续测评。
- 谈风险先套"资产—威胁—脆弱性"三角，再给处置措施。

## Anti-patterns
- 把等保当"买测评"，未真正落地三重防护与持续运维。
- 只做边界防火墙，忽视主机/应用/数据层防护（纵深不足）。

## Key Takeaways
1. CIA 三性 + 等保 2.0 五级、一个中心三重防护。
2. 等保流程：定级→备案→整改→测评→监督。
3. 风险评估 = 资产×威胁×脆弱性。
4. 关基重点保护；合规底线含数据安全法/个保法。
